## 已修复问题：证据 → 发现 → 改动

| 优先级 | 原代码证据与问题 | 改动与验证 |
|---|---|---|
| P1 | `_metric_block`失败时自动使用预设值；10Y缺失静默采用4.0%。真实行情下仍保存总分 | 缺失用None；手动启用才采用输入值；显示权重覆盖率；缺失/手动/演示不保存正式记录。面板回归测试覆盖 |
| P1 | 共振与红线扫描全部因子，零权重也能拉高总分 | 仅启用因子参与；禁用的高分因子不触发警报/托底 |
| P1 | 模型全零权重恢复默认，UI用零权重重新计算贡献 | 生效权重和贡献统一由模型返回；显示实际配置，贡献非零且可复核 |
| P1 | `score_technical`把无效SMA当成0乖离；行情长度未验证 | 拒绝非有限/非法输入，ETF至少200个有效观测；失败进入明确演示图 |
| P1 | FRED非金融公司权益被固定比例校准为上市总市值 | 移除校准常量；同季度代理比值仅展示，不参与巴菲特评分。口径依据见下方FRED来源 |
| P1 | 10Y补全写在2Y失败分支；2Y成功时可能保留失败10Y | 两个期限独立检查，CNBC/东方财富/FRED补缺；有专门回归用例 |
| P1 | `_SSL_CTX`关闭证书与主机名验证；代理全局状态不会在清空时复位 | 恢复TLS验证，代理上下文隔离，yfinance共享状态通过锁保护；不改进程环境变量 |
| P1 | CSV直接覆盖，无锁；不同权重与手动校准可能混合 | 拆出持久化模块，线程/进程锁与临时文件原子替换；按模型与配置隔离；写失败保留原文件 |
| P2 | 关闭自动获取后仍先拉全部数据，再丢弃结果 | 关闭时只调用ETF缓存函数；测试确认没有宏观请求 |
| P2 | 同一缓存键包含ticker，页面重运行重复获取所有宏观项 | ETF和宏观分开缓存，独立宏观来源并发；测试确认页面重运行宏观只取一次 |

| P2 | 取信用最新有效值，却显示第一条缺失观测的日期 | 值与日期共同筛选，日期始终与所用读数配对 |
| P2 | Multpl标题被span及换行隔开；原正则未可靠匹配 | 去掉脚本/样式、统一文本空白；实际页面重验成功 |

## 清理的冗余

移除未使用的pandas/numpy/time导入、GDP增速函数与固定巴菲特校准常量。删除UI旧版Title-case评分适配器及多套因子/权重映射；权重控件与指标渲染使用统一元数据。恐慌指数重复配置块合并，10Y采用同一手动配置链路。行情图拆为独立构造函数，历史读写不再由数据抓取模块承担。

本次优化增加了缺失状态、锁、校验与回归覆盖，目标是行为可靠和职责清晰，不以总行数下降为唯一标准。

## 最终职责

| 模块 | 负责 |
|---|---|
| `app.py` | 配置、两个缓存、覆盖率与状态提示、面板 |
| `data_fetcher.py` | HTTP、TLS、代理、并发、解析与备用链 |
| `risk_model.py` | 有效值、启用因子、权重、贡献、共振/红线、近似情景 |
| `risk_history.py` | 评分配置标识、按行情日记录、锁、原子写入、旧CSV兼容 |
| `charts.py` | 价格/均线/成交量图，评分不可用时仍可展示 |

## 真实数据源检查及限制

本次真实请求：CNBC两个期限、FRED信用、CNN情绪返回数据；Multpl修复后读取成功；东方财富最新记录读取成功。Yahoo返回限流，GuruFocus返回HTTP 403，这两项的获取失败已被正确标记。没有用模拟价格或FRED代理市值把失败伪装为自动成功。

外部限流与访问拒绝无法通过单元测试消除。目前主行情仍依赖Yahoo，上市总市值指标仍依赖GuruFocus；[功能6](FEATURE_OPTIONS.md)专门解决真实备用源与最近有效快照。不同期限/来源的观测时刻也可能不完全一致，应结合来源检查。

## 仍需选择的模型能力

- 当前技术与情绪规则偏向过热；负乖离可能导致评分下降，即使市场正承受严重下跌。建议单独建立下跌压力维度，并通过真实回测检验。
- 仅有当期利差不能判断“倒挂后解挂”；要加入曲线历史状态。
- 固定阈值并不等价于统计分位数；除信用外目前仍是经验阈值。
- 监测已按用户要求收敛为VOO；全市场宏观输入并非ETF专有指标。
- 不打开应用便不会积累新的历史；后台采集与通知尚待选择。
